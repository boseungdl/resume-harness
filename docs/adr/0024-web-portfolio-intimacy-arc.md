# 0024. 웹 포폴 여정 — 친밀도 아크와 감사의 설계

날짜: 2026-08-07

## 상태

승인됨 (여정 콘텐츠 구조·감정 설계. 본문 문장은 초안 — 사용자 확정 대기)

## 맥락

여정의 목적이 "같이 일하고 싶게 + 하나씩 친해지게"로 명시되고, 버튼을 누른 방문자의 시간에 대한 감사가 전달돼야 한다는 요구. 심리상담사(자기개방 이론)·UX 라이터 2관점 리뷰로 설계.

## 결정

- **7챕터 친밀도 아크** (사회적 침투 이론 — 표면→중심, 취약성은 유능함 뒤에):
  1 사실(지금 하는 일) → 2 행동(문제 방식) → 3 유능함 앵커(191명) → 4 관계(첫인상은 단호, 겪으면 반대 — 기존 1장에서 이동: 실적 뒤에 두면 약점 자백이 스타일이 된다) → 5 취약성(비전공 부족+대응, 기존 '꾸준함' 장 흡수) → 6 신뢰(재연락 사실) → 7 가치·미래(처음으로 독자를 직접 호명, 미래형 마감).
  톤: 격식 완결형 → 문장 점점 짧게 → 7장에서 거리 최소.
- **감사 3점 원칙** (Algoe find-remind-bind, 총 3회 상한):
  (a) 시작 = 감사 금지, 계약으로 대체: "3분, 아껴 쓰겠습니다. 일곱 번 멈춥니다." + 로봇 끄덕임(Yes 클립) + 700ms 뒤 출발.
  (b) 절반(4번째 수집 직후) = 말 대신 개방 심화 예고: "절반을 걸으셨습니다 — 여기부터는 조금 더 솔직한 이야기입니다."
  (c) 엔딩 = 구체 행동 회수 + 1문장 감사 + bind: 걸은 기록(m·시간) 주입 → "일곱 번 멈춰 읽어주신 시간, 고맙습니다." → "다음 구간은, 만나서 걷고 싶습니다." 3행 스태거. 로봇은 Wave 후 끄덕임.
  경계: 감사는 방문자의 행동을 향한다(속성 칭찬=아부). 자기낮춤 감사 금지.
- **화자 규칙**: 로봇은 말하지 않는다 — 동작만(인사·끄덕임). 화면의 모든 말은 지원자 1인칭. 팝업 버튼은 독자 대사("알겠습니다") 금지 → 무주어 행동("계속 걷기 →", 마지막만 "마지막 구간으로 →").
- **동행의 언어**: PROFILE SYNC → "함께 걷는 중"/"함께 걸었습니다", 만남→나눈 질문, 걸은 거리→같이 걸은 거리, 여정 시간→함께한 시간. 만남 라벨은 서수(첫 번째~마지막 질문)로 진행을 알린다.
- 타이핑 34→28ms — "3분" 약속은 신뢰 챕터의 담보.

## 결과

- story.js 재배열·초안 작성(플레이스홀더 마커 유지) — 최종 문장은 사용자 확정.
- 기각: 시작 시점의 "감사합니다"(선불 청구서), 로봇 대사(마스코트 화법), 버튼 7단 문구 변화(장치로 읽힘), 후반 게이트 자동 해제(읽기 강제 구조 유지).
