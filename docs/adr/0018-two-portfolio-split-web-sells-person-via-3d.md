# 0018. 포폴 이원화 — PDF는 기술 증명, 웹 포폴은 사람·호기심(3D 서사)

날짜: 2026-08-06

## 상태

승인됨

## 맥락

기존 포폴(`portfolio/index2.html`, PDF 지향)은 프로젝트·기술 스택 밀도가 높아 인사담당자가 소화하기 어렵다. HR을 첫 독자로 하는 접근 쉬운 웹 포폴이 필요했다. 단순히 "쉬운 버전"을 만들 수도 있었지만, 자소서 목적함수(ADR-0014: 사람을 판다, 호기심이 성공 기준)와 정렬하는 선택지를 검토했다.

## 결정

포트폴리오를 두 개로 이원화한다.

- **PDF 포폴** — 기술 증명 전담. 독자는 시니어·면접관. 기존 그대로.
- **웹 포폴** — 사람 전담. 독자는 인사담당자. 성공 기준은 "만나보고 싶다"(호기심) + "감각 있네"(인상).

웹 포폴의 형식 자체가 증명이다: 전환점 챕터별 3D 씬을 스크롤로 통과하는 페이지를 AI로 혼자 만들어냄으로써 "AI를 잘 쓴다"를 말이 아니라 실물로 증명한다. 세부 결정:

- 독자 여정: 이력서·지원서 링크로 사전 맥락 없이 진입 → 독립 완결, 첫 30초 승부, 조작 요구 금지(스크롤만).
- 콘텐츠 축: 일하는 방식·가치관 + 성장 서사. 전환점(사건) 중심·연도 비표기 — 서사는 살리고 "4년 취준" 기간 계산은 차단(약점 비노출).
- 프로젝트는 독립 섹션 없이 서사 속 장면으로만. 상세는 PDF 포폴·깃헙 링크로 위임.
- 텍스트는 1인칭 내레이션, 담백.
- 콘텐츠는 UI를 보며 확정 — 챕터·텍스트를 설정 파일로 분리한 데이터 주도 구조.
- 스택: Vite + Three.js + GSAP. 데스크톱 기준(모바일 무대응), 자동 품질 스케일링.
- 배포: 별도 공개 repo `boseungdl.github.io`(GitHub Pages) — 이력서에 붙는 URL이므로 되돌리기 어렵다.

## 결과

- 두 포폴의 역할이 겹치지 않아 각자 순수해진다 — 웹 포폴에 기술 섹션을 추가하고 싶은 유혹은 이 ADR 위반.
- 실제 LLM 챗봇은 배제됨(통제 불가 답변·비용·방치 리스크) — "AI 증명"은 결과물 퀄리티가 담당.
- 웹 포폴 텍스트에도 자소서 절대 규칙(비유 금지·담백·약점 비노출)이 적용된다.
